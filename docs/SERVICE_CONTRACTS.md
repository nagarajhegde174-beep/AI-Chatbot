# SERVICE_CONTRACTS.md — Service Contracts

The explicit, versioned agreements between NexaAI services.

**Status: specified, not implemented.** Every contract here is a commitment that Phase 1 and
later must honour. A change to any contract in this document updates this document in the same
change ([`RULES.md`](RULES.md) §12).

Related: [`ARCHITECTURE.md`](ARCHITECTURE.md) for the system,
[`DECISIONS.md`](DECISIONS.md) for why the boundaries are where they are.

---

## 1. General conventions

### 1.1 URL spaces

| Space | Audience | Path |
|---|---|---|
| Public | Browser, via the gateway only | `/api/v1/**` |
| Inter-service | Service to service, never from the internet | `/internal/v1/**` |
| Operational | Infrastructure only | `/actuator/**` |

**Rules.**
- The browser never calls a service port. Only the gateway is public.
- `/internal/**` and `/actuator/**` are denied at the edge **and** by the gateway. Two
  independent locks, because one configuration mistake should not expose internals.
- Every path is versioned. Breaking changes mean a new version, never an in-place change.

### 1.2 Headers

| Header | Direction | Purpose |
|---|---|---|
| `Authorization: Bearer <token>` | client → service | Access token. The only accepted credential. |
| `X-Correlation-Id` | everywhere | Generated by the gateway if absent; propagated on every hop; returned to the client |
| `X-Request-Id` | client → service | Optional client-supplied id, adopted as the correlation id if well-formed |
| `Accept-Language` | client → service | Reserved for Phase 10 localisation. Not used in Phase 1 |

### 1.3 Status codes

| Code | Meaning here |
|---|---|
| 200 / 201 / 204 | Success. 201 carries a `Location` on creation. |
| 400 | Malformed request. The message names the field. |
| 401 | Missing, invalid, expired or revoked token. Never a hint about which. |
| 403 | Authenticated but not permitted. **Reserved for ADMIN**, to avoid leaking existence. |
| 404 | Does not exist, **or** exists but is not yours. Deliberately ambiguous. |
| 409 | Conflict, e.g. email already registered. |
| 422 | Semantically invalid, e.g. a password failing policy. |
| 429 | Rate limited. Always with `Retry-After`. |
| 502 / 504 | An upstream service failed or timed out. |
| 503 | Deliberately unavailable. Circuit breaker open. |

**403 versus 404.** A `USER` asking for another user's resource gets 404 whether or not it
exists. 403 confirms it exists, which is an enumeration channel
([`SECURITY.md`](SECURITY.md) §4.2).

### 1.4 Error envelope

Every service, identically shaped:

```json
{
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "Email or password is incorrect.",
    "correlationId": "0f9c1e2a-4b7d-4f1e-9a3c-2d5e6f708192",
    "timestamp": "2026-01-15T10:30:00Z",
    "details": null
  }
}
```

Rules:
- `code` is a stable machine-readable identifier, UPPER_SNAKE_CASE. Clients branch on it.
- `message` is human-readable, safe to display, and **never** a stack trace, a SQL message or a
  provider's raw error.
- `correlationId` is always present, so a user can report a real problem.
- `details` carries field-level validation errors only, and never echoes a submitted secret:
  `{"email": "must be a valid address"}`.

### 1.5 Pagination

Request: `?page=0&size=20`, `size` capped at 100.

```json
{
  "content": [],
  "page": 0,
  "size": 20,
  "totalElements": 137,
  "totalPages": 7,
  "last": false
}
```

Never offset pagination on a large table. If a table can grow without bound, keyset pagination
is used and this shape does not apply.

### 1.6 Timestamps and identifiers

- **Timestamps:** ISO-8601 UTC with an offset, `2026-01-15T10:30:00Z`. Never a local time, never
  a bare timestamp.
- **Identifiers:** UUID v4 in API payloads. Exposed as `string` and treated as opaque by
  clients. Internal primary keys are their own concern and never appear in a contract.
- **Enum values:** UPPER_SNAKE_CASE.

### 1.7 Idempotency

`POST` that creates something accepts `Idempotency-Key`. The same key replays the original
response instead of creating a duplicate. Scoped per caller, with a defined retention window.

## 2. Boundary endpoint

Every service implements this. It exists so a boundary violation is **visible** rather than
assumed, and it is what a Phase 0 rule check or an operator can assert.

### `GET /internal/v1/{service}/info`

```json
{
  "service": "auth-service",
  "version": "0.1.0",
  "role": "Credentials, tokens, account status",
  "port": 8081,
  "database": "nexa_auth",
  "listensKafka": true,
  "consumes": ["none"],
  "produces": ["auth.user.registered.v1"]
}
```

`database` is `null` for `api-gateway` and `ai-service`. That field is the boundary assertion:
a service that owns a database must name exactly one, and it must be its own.

**Not implemented in Phase 0** ([`DECISIONS.md`](DECISIONS.md) ADR-015). It ships with each
service, in that service's own phase.

## 3. DTO boundaries

### 3.1 DTOs are duplicated deliberately

Two services exchanging a payload do **not** share a type. Each declares its own, shaped to its
own need. [`SERVICE_CONTRACTS.md`](DECISIONS.md) §13 / ADR-013 explains why.

### 3.2 Entity types never cross a boundary

A JPA entity, a database row and an API payload are three different things. What crosses is a
DTO.

| Never crosses | Why |
|---|---|
| JPA entity | Leaks the schema, and forces lazy-loading decisions onto the caller |
| Database row | Same |
| Internal enum with ordinal values | Ordinals change when someone reorders them |
| Internal exception | Leaks implementation detail |

### 3.3 Enumerations shared across services

These string values are part of a contract and must not be renamed:

| Enum | Values | Owner |
|---|---|---|
| Role | `USER`, `ADMIN` | auth-service |
| Account status | `ACTIVE`, `SUSPENDED`, `DEACTIVATED` | auth-service |
| Document status | `UPLOADING`, `PROCESSING`, `READY`, `FAILED` | document-service |
| Subscription status | `ACTIVE`, `PAST_DUE`, `CANCELLED`, `EXPIRED` | subscription-service |
| Plan interval | `MONTHLY`, `YEARLY` | subscription-service |
| Model provider | `OPENAI`, `GEMINI`, `GROQ` | ai-service |
| Citation type | `DOCUMENT` | chat-service |

**Adding a value is a compatible change.** Renaming or removing one is not; it requires a new
version.

### 3.4 Sensitive fields never cross a boundary

| Field | Rule |
|---|---|
| Password hash | Never leaves auth-service, in any DTO, ever |
| Refresh token | Never returned. Only the token *value* is issued, and only at issue time |
| API keys, key secrets, webhook secret | Never in any response, including admin endpoints |
| `jti` of another user's token | Never in any response |
| Prompt content in analytics | Never. Analytics carries counts, not content |

## 4. API Gateway

Port 8080. Owns no database.

### 4.1 Responsibilities

- Terminate and validate the access token (RS256), rejecting invalid requests before routing.
- Route by path prefix to the owning service.
- Generate and propagate `X-Correlation-Id`.
- Apply rate limits and body size limits.
- Apply CORS from a configured allowlist.
- Aggregate health for orchestration.
- Deny `/internal/**` and `/actuator/**` from external access.

**The gateway holds no business logic.** A route that computes something belongs in the service
that owns the data.

### 4.2 Route table

| Public path prefix | Target | Phase |
|---|---|:--:|
| `/api/v1/auth/**` | `auth-service:8081` | 1 |
| `/api/v1/users/me`, `/api/v1/admin/users/**` | `user-service:8082` | 2 |
| `/api/v1/chat/**` | `chat-service:8083` | 3 |
| `/api/v1/models/**` | `ai-service:8084` | 4 |
| `/api/v1/documents/**` | `document-service:8085` | 6 |
| `/api/v1/rag/**` | `rag-service:8086` | 7 |
| `/api/v1/subscriptions/**`, `/api/v1/plans/**` | `subscription-service:8087` | 9 |
| `/internal/v1/chat/**` | `chat-service:8083` | inter-service only |
| `/internal/v1/ai/**` | `ai-service:8084` | inter-service only |
| `/internal/v1/rag/**` | `rag-service:8086` | inter-service only |

### 4.3 Per-route policy

| Policy | Value |
|---|---|
| Authentication | Required except where listed as public |
| Rate limit | Per concern: auth 10/min, chat 60/min, api 300/min per IP |
| Body size | 25 MB on upload routes, 1 MB elsewhere |
| Timeout | 30 s default, 600 s on streaming routes |
| Retry | Never on a non-idempotent method |
| Circuit breaker | Per downstream service |

**Never retry a `POST`.** A retried `POST /messages` bills the user twice.

### 4.4 Gateway endpoints

| Method | Path | Purpose | Phase |
|---|---|---|:--:|
| GET | `/actuator/health` | Aggregate health | 3 |
| GET | `/internal/v1/gateway/info` | Services and routes | 3 |
| GET | `/.well-known/jwks.json` | RS256 public key set, for verifiers | 3 |
| GET | `/healthz` | NGINX-facing liveness | 0 |

## 5. Auth Service

Port 8081. Owns `nexa_auth`. The only service that ever handles a password.

### 5.1 Public endpoints

| Method | Path | Auth | Purpose |
|---|---|:--:|---|
| POST | `/api/v1/auth/register` | no | Create an account |
| POST | `/api/v1/auth/login` | no | Exchange credentials for tokens |
| POST | `/api/v1/auth/refresh` | no | Rotate the refresh token |
| POST | `/api/v1/auth/logout` | bearer | Revoke the current refresh token |
| POST | `/api/v1/auth/logout-all` | bearer | Revoke every refresh token |
| GET | `/api/v1/auth/me` | bearer | Current principal summary |
| POST | `/api/v1/auth/password/forgot` | no | Request a reset |
| POST | `/api/v1/auth/password/reset` | no | Complete a reset |
| POST | `/api/v1/auth/email/verify` | no | Verify an email |

### 5.2 Internal endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/internal/v1/auth/info` | Boundary assertion |
| POST | `/internal/v1/auth/introspect` | Validate a token and return its claims |
| GET | `/internal/v1/auth/users/{id}/status` | Account status, for user-service and chat-service |

### 5.3 Principal claims

```json
{
  "sub": "9f1c7b2e-4a3d-4c8f-b1e2-5d7a9c3e0f14",
  "iss": "nexa-auth-service",
  "aud": "nexaai-web",
  "roles": ["USER"],
  "status": "ACTIVE",
  "jti": "b7d9e1a4-3c2f-4a6b-8e5d-1f3a7b9c2e60",
  "iat": 1768473000,
  "exp": 1768473900
}
```

**Verification requirements, all mandatory.**
- `alg` must be exactly `RS256`. `alg: none` and an HS256 token signed with the public key are
  rejected.
- `iss` must be `nexa-auth-service`.
- `aud` must include `nexaai-web`.
- `exp` must be in the future.
- `status` must be `ACTIVE`. A suspended account's token is rejected even before it expires.

### 5.4 Registration

```http
POST /api/v1/auth/register
Content-Type: application/json
Idempotency-Key: 7f3a...

{ "email": "user@example.com", "password": "a-long-passphrase", "displayName": "Ada" }
```

**201 Created**
```json
{
  "userId": "9f1c7b2e-4a3d-4c8f-b1e2-5d7a9c3e0f14",
  "email": "user@example.com",
  "displayName": "Ada",
  "roles": ["USER"],
  "status": "PENDING_VERIFICATION",
  "createdAt": "2026-01-15T10:30:00Z"
}
```

**No token is returned from registration.** The account must verify its email first. This
prevents mass unverified registration and keeps the verification path real.

**409** if the email is already registered. The message must not reveal whether the existing
account is verified.

### 5.5 Login

```http
POST /api/v1/auth/login
{ "email": "user@example.com", "password": "a-long-passphrase" }
```

**200 OK**
```json
{
  "accessToken": "eyJhbGciOiJSUzI1NiIs...",
  "refreshToken": "9d1f...",
  "tokenType": "Bearer",
  "expiresIn": 900,
  "user": {
    "userId": "9f1c7b2e-4a3d-4c8f-b1e2-5d7a9c3e0f14",
    "email": "user@example.com",
    "displayName": "Ada",
    "roles": ["USER"]
  }
}
```

**Failure.** A wrong password and an unknown email return the **same** body and the **same**
status:

```json
{
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "Email or password is incorrect.",
    "correlationId": "...",
    "timestamp": "...",
    "details": null
  }
}
```

Timing must also be indistinguishable, which means a dummy hash is computed when the email does
not exist ([`SECURITY.md`](SECURITY.md) §2.1).

**429** after too many failures for one account.

### 5.6 Refresh

```http
POST /api/v1/auth/refresh
{ "refreshToken": "9d1f..." }
```

Returns a **new** access token and a **new** refresh token. The old refresh token is revoked. If
a revoked token is presented, the entire token family is revoked, because presentation of a
revoked token indicates theft.

**401** on an unknown, expired, already-used or revoked token.

### 5.7 Internal: introspect

```http
POST /internal/v1/auth/introspect
Authorization: Bearer <the token to verify>
```

**200**
```json
{ "active": true, "sub": "...", "roles": ["USER"], "status": "ACTIVE", "exp": 1768473900 }
```

**200 with `"active": false`** for an invalid token, rather than 401, so a caller can distinguish
"invalid" from "I called this wrongly". Never returns why.

### 5.8 Auth Service data

| Table | Purpose | Notes |
|---|---|---|
| `auth_user` | Email, password hash, status, role | No plaintext password, ever |
| `refresh_token` | Hashed token, family id, expiry, revoked at | Rotation and theft detection |
| `token_denylist` | Revoked `jti` until natural expiry | Mirrored to Redis for speed |
| `login_attempt` | Failures per account, for lockout | Retention-limited |
| `email_verification` | Single-use token, expiry | |
| `password_reset` | Single-use token, expiry | |

### 7.1 Endpoints

| Method | Path | Auth | Purpose |
|---|---|:--:|---|
| GET | `/api/v1/chat/conversations` | bearer | List own conversations |
| POST | `/api/v1/chat/conversations` | bearer | Create |
| GET | `/api/v1/chat/conversations/{id}` | bearer | One, with ownership check |
| PATCH | `/api/v1/chat/conversations/{id}` | bearer | Rename, change model |
| DELETE | `/api/v1/chat/conversations/{id}` | bearer | Delete |
| GET | `/api/v1/chat/conversations/{id}/messages` | bearer | History, paginated |
| POST | `/api/v1/chat/conversations/{id}/messages` | bearer | Send a message, **SSE** |

| DELETE | `/api/v1/chat/conversations/{id}/messages/{messageId}` | bearer | Delete a message |

### 7.2 Streaming contract

```
POST /api/v1/chat/conversations/{id}/messages
Content-Type: application/json
Accept: text/event-stream

{ "content": "What does the cancellation policy say?", "ragEnabled": true }
```

**Response: `text/event-stream`**

```
event: meta
data: {"messageId":"...","conversationId":"...","model":"gpt-4o-mini","provider":"OPENAI"}

event: retrieval
data: {"used":true,"passageCount":3,"sources":[{"documentId":"...","title":"terms.pdf","chunkIndex":4}]}

event: token
data: {"text":"The cancellation window is "}

event: token
data: {"text":"30 days."}

event: citation
data: {"index":1,"documentId":"...","title":"terms.pdf","chunkIndex":4}

event: usage
data: {"promptTokens":812,"completionTokens":47,"totalTokens":859}

event: done
data: {"messageId":"...","status":"COMPLETE","finishedAt":"2026-01-15T10:30:04Z"}

event: error
data: {"code":"AI_PROVIDER_TIMEOUT","message":"The model did not respond in time.","retryable":true}
```

**Event semantics.**

| Event | Frequency | Meaning |
|---|---|---|
| `meta` | exactly once, first | Identifiers and the model selected |
| `retrieval` | 0 or 1 | What was retrieved, if RAG was on |
| `token` | many | One text fragment. Concatenate in order |
| `citation` | 0+ | A source used. Must accompany any grounded answer |
| `usage` | exactly once | Token counts for metering |
| `done` | exactly once, last | Terminal success |
| `error` | at most once, last | Terminal failure. No `done` after it |

**Rules.**
- Exactly one terminal event, `done` or `error`.
- An `error` after some `token` events means the answer is **partial**. The stored assistant
  message is marked incomplete, never complete.
- The client must tolerate a dropped connection: it reconnects and reads the persisted message.
- Every proxy hop must disable buffering, or the stream arrives all at once
  ([`DECISIONS.md`](DECISIONS.md) ADR-021).

### 7.3 Consumes

| Topic | Action |
|---|---|
| `user.status.changed.v1` | Refuse new messages for a suspended account |
| `subscription.activated.v1` | Update the cached entitlement |
| `document.indexed.v1` | Note which conversations predate the document |

### 7.4 Produces

| Topic | Action |
|---|---|
| `chat.message.completed.v1` | A completed turn, with token counts and latency |

### 7.5 Chat Service data

| Table | Purpose |
|---|---|
| `conversation` | Owner, title, model, RAG flag, last activity |
| `message` | Conversation, role, content, model, token counts, status, citations |
| `message_citation` | Message, document id, chunk index, excerpt |
| `conversation_model_history` | Model changes, so a memory reset is explainable |

### 7.6 Quota enforcement

Checked **before** the provider is called, using the entitlement from Subscription Service. A
refusal returns 429 with the allowance, the used count and the reset time — so the client can
show something useful rather than a bare error.

## 8. AI Service

Port 8084. **Stateless.** Owns no database.

### 8.1 Internal endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/internal/v1/ai/completions` | Non-streaming completion |
| POST | `/internal/v1/ai/stream` | Streaming completion |
| GET | `/internal/v1/ai/models` | Available models for a given provider |
| GET | `/internal/v1/ai/health` | Per-provider reachability |

There is **no public route** to this service. The catalogue the frontend renders is proxied
through the gateway from `/api/v1/models/**`, so the browser still has exactly one entry point.

### 8.2 Completion request

```json
{
  "provider": "OPENAI",
  "model": "gpt-4o-mini",
  "systemPrompt": "...",
  "messages": [
    { "role": "SYSTEM", "content": "..." },
    { "role": "USER", "content": "..." },
    { "role": "ASSISTANT", "content": "..." },
    { "role": "USER", "content": "..." }
  ],
  "temperature": 0.7,
  "maxOutputTokens": 2048,
  "requestId": "0f9c1e2a-4b7d-4f1e-9a3c-2d5e6f708192"
}
```

`maxOutputTokens` is **required**. A missing bound is an unbounded bill.

### 8.3 Response

```json
{
  "requestId": "0f9c1e2a-4b7d-4f1e-9a3c-2d5e6f708192",
  "provider": "OPENAI",
  "model": "gpt-4o-mini",
  "content": "...",
  "finishReason": "STOP",
  "usage": { "promptTokens": 812, "completionTokens": 47, "totalTokens": 859 },
  "latencyMs": 1423
}
```

### 8.4 Provider errors

Classified, never passed through raw:

| Code | HTTP | Retryable | Cause |
|---|:--:|:--:|---|
| `AI_NOT_CONFIGURED` | 503 | no | Missing key. Fails fast at startup, so this is rare |
| `AI_RATE_LIMITED` | 429 | yes, with backoff | Provider throttling |
| `AI_TIMEOUT` | 504 | yes, once | Provider exceeded the deadline |
| `AI_CONTENT_FILTERED` | 422 | no | Provider refused the content |
| `AI_PROVIDER_ERROR` | 502 | yes | Anything else from the provider |
| `AI_CIRCUIT_OPEN` | 503 | yes, later | Breaker open after repeated failures |
| `AI_MODEL_NOT_FOUND` | 404 | no | Unknown model for that provider |

### 8.5 Produces

| Topic | Payload |
|---|---|
| `ai.inference.completed.v1` | provider, model, token counts, latency, success flag, **no prompt or completion content** |

This is the metering source ([`PRD.md`](PRD.md) §9). It carries counts, never content.

## 9. Document Service

Port 8085. Owns `nexa_document`. Never embeds ([`ARCHITECTURE.md`](ARCHITECTURE.md) §7.1).

### 9.1 Endpoints

| Method | Path | Auth | Purpose |
|---|---|:--:|---|
| POST | `/api/v1/documents` | bearer | Upload, `multipart/form-data` |
| GET | `/api/v1/documents` | bearer | List own documents |
| GET | `/api/v1/documents/{id}` | bearer | Metadata |
| GET | `/api/v1/documents/{id}/content` | bearer | Extracted text, owner only |
| DELETE | `/api/v1/documents/{id}` | bearer | Delete and emit the event |

Content is served **only** through the authorised controller. Files are never exposed by a
direct URL, never stored under a servable path, and never served with their original content
type ([`SECURITY.md`](SECURITY.md) §7).

### 9.2 Upload

```
POST /api/v1/documents
Content-Type: multipart/form-data; boundary=...

file=@terms.pdf
```

**201 Created**
```json
{
  "documentId": "...",
  "title": "terms.pdf",
  "originalFilename": "terms.pdf",
  "contentType": "application/pdf",
  "sizeBytes": 284913,
  "status": "UPLOADING",
  "chunkCount": 0,
  "createdAt": "2026-01-15T10:30:00Z"
}
```

**413** if over the size limit. **415** if the content type is not allowed, or if the file's
content does not match its extension ([`SECURITY.md`](SECURITY.md) §7).

### 9.3 Status transitions

`UPLOADING → PROCESSING → READY | FAILED`

**`FAILED` shape**
```json
{
  "documentId": "...",
  "status": "FAILED",
  "failureReason": "This PDF is password protected and could not be read.",
  "failedAt": "2026-01-15T10:31:00Z"
}
```

The reason is human-readable. A stack trace never reaches a client.

### 9.4 Produces

| Topic | When | Payload |
|---|---|---|
| `document.uploaded.v1` | On acceptance | documentId, userId, filename, contentType, sizeBytes |
| `document.chunked.v1` | After chunking | documentId, userId, title, chunks[] with index and text |
| `document.indexed.v1` | RAG confirms indexing | documentId, chunkCount, embeddingModel |
| `document.deleted.v1` | On delete | documentId, userId |
| `document.processing.failed.v1` | On failure | documentId, reasonCode |

### 9.5 Document Service data

## 10. RAG Service

Port 8086. Owns `nexa_rag`. The only service that loads pgvector.

### 10.1 Internal endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/internal/v1/rag/retrieve` | Similarity search, tenant-scoped |
| POST | `/internal/v1/rag/upsert` | Store embeddings |
| POST | `/internal/v1/rag/documents/{id}/delete` | Remove a document's vectors |
| GET | `/internal/v1/rag/health` | Database and extension health |

### 10.2 Retrieve

```json
{ "userId": "...", "query": "cancellation policy", "topK": 5, "documentIds": null, "minScore": 0.2 }
```

`documentIds` optionally narrows to specific documents. `userId` is **required and never
optional**: there is no unscoped search, so a cross-user leak cannot be expressed.

**200**
```json
{
  "passages": [
    {
      "documentId": "...",
      "documentTitle": "terms.pdf",
      "chunkIndex": 4,
      "text": "Cancellations must be received within 30 days...",
      "score": 0.87,
      "citationIndex": 1
    }
  ],
  "used": true,
  "embeddingModel": "text-embedding-3-small"
}
```

**Every passage carries `documentId` and `chunkIndex`.** Without them a citation is impossible.

### 10.3 Tenant isolation

```sql
SELECT document_id, chunk_index, text, content
FROM document_embedding
WHERE user_id = :userId          -- in the query, not applied afterwards
  AND (:documentIds::uuid[] IS NULL OR document_id = ANY(:documentIds))
ORDER BY embedding <=> :queryVector
LIMIT :topK;
```

`user_id` is a **column filter inside the query**. Filtering results after retrieval is a data
leak, and it is tested directly ([`TEST_PLAN.md`](TEST_PLAN.md) §4, Phase 7).

|---|---|---|
| `document.chunked.v1` | Embed and store | Deduplicate on event id |
| `document.deleted.v1` | Delete that document's vectors | Naturally idempotent |

### 10.5 RAG Service data

| Table | Purpose |
|---|---|
| `document_embedding` | userId, documentId, chunkIndex, text, embedding `vector(1536)`, model |
| `processed_event` | Event ids already applied, for idempotency |

Index: HNSW on the vector column, plus a b-tree on `(user_id, document_id)`.

### 11.4 Webhook

```
POST /webhooks/razorpay
X-Razorpay-Signature: <HMAC-SHA256 of body + secret>
```

Processing order, strictly:

1. Read the **raw** body. A re-serialised body will not match the signature.
2. Verify the HMAC with a **constant-time** comparison.
3. Reject on mismatch, with no detail.
4. Deduplicate on the provider payment id.
5. Record the payment.
6. Grant entitlements.
7. Publish `subscription.activated.v1`.

**The webhook is the source of truth.** The browser redirect is a convenience and never
activates a subscription, so closing the tab cannot lose a payment.

### 12.2 Envelope

Every event uses one envelope:

```json
{
  "eventId": "b7d9e1a4-3c2f-4a6b-8e5d-1f3a7b9c2e60",
  "eventType": "chat.message.completed.v1",
  "eventVersion": 1,
  "occurredAt": "2026-01-15T10:30:04Z",
  "correlationId": "0f9c1e2a-4b7d-4f1e-9a3c-2d5e6f708192",
  "actorId": "9f1c7b2e-4a3d-4c8f-b1e2-5d7a9c3e0f14",
  "subjectId": "3c5a...",
  "payload": { }
}
```

**Rules.**
- `eventId` is the idempotency key. A consumer deduplicates on it.
- `correlationId` ties the event to the request that caused it. Without it, a bug report cannot
  be traced.
- `actorId` is who caused it; `subjectId` is what it happened to. An admin acting on a user has
  different values.
- **No secret, no prompt content and no document content in any payload.** Analytics needs
  counts, and counts are what it gets.

### 12.3 Naming

`<domain>.<entity>.<past-tense-verb>.v<N>`, lowercase, dot-separated.

Facts, never commands: `chat.message.completed.v1`, not `send-chat-message.v1`. A consumer
should not need to know what to do, only what happened.

### 12.4 Evolution

| Change | Compatible |
|---|---|
| Add a field | yes |
| Add an enum value | yes |
| Remove a field | no — deprecate, retain, remove at a version bump |
| Rename or retype a field | no |
| Change a field's meaning | no — that is a new event type |

A consumer must ignore unknown fields. A producer must never change the meaning of an existing
field.

### 12.5 Delivery

At-least-once. Therefore:

- Every consumer is idempotent, deduplicating on `eventId`.
- Events are not delivered in order across partitions; ordering holds only within a partition,
  and only for the same key.
- A consumer must tolerate an event arriving late, or twice, or after a restart.

## 13. Contract change discipline

| Change | Action |
|---|---|
| A new endpoint | Add to this document in the same change |
| An endpoint removed or its path changed | New version, deprecate the old, document both |
| A field added | Add here; consumers ignore unknown fields |
| A field removed | Deprecate, retain, remove at a version bump |
| A new event | Add to §12 with its owner, consumers, partitions, key and retention |
| A topic's owner changes | A new topic. One producer owns a topic for its lifetime |
| Any change | Update this document **in the same commit** ([`RULES.md`](RULES.md) §12) |

**A contract change without a documentation change is an incomplete change.** The document is
the shared artefact that replaces a shared code module
([`DECISIONS.md`](DECISIONS.md) ADR-013).
